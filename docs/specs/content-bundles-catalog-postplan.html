4. Code fixes shipped with this postplan

  • Fixed: fallback clobber. GenericCatalogDiscoverer persisted the first successful candidate URL, so Dominator 404 + Main success rewrote CatalogUrl to Main while SelectedCatalogId stayed Dominator: dropdown showed Dominator, grid showed Main's single card. The resolved URL is now only persisted when the preferred (first) candidate wins. Regression test: DiscoverAsync_SelectedCatalogFailsSiblingSucceeds_DoesNotClobberSubscriptionUrlAsync.
  • Fixed: edit discard. ContentLibraryViewModel.EditContentAsync copied back only name/description/type/game/tags/extends/metadata, silently dropping matrix (BundledItems), Releases, UpstreamSync, PublisherType, IsFeatured/FeaturedBadge, Addons/AddonReleases. All are now copied back on save.
  • Fixed: upstream shown twice. Tracked items rendered the static fallback list and the live upstream preview with no distinction, and a static release whose version equaled the preview version appeared twice. The static section now shows a fallback note, and static releases duplicating a preview version are hidden (UpstreamDuplicateReleaseConverter). Fallbacks stay editable (Add Release kept).
  • Fixed: false "update available" on same-version siblings. ReconcileInstalledFamilyItems treated any uninstalled family card as newer, so a downloaded language/resolution variant was flagged as updatable to an identical-version sibling. Updates now require a strictly newer version (ContentStateService.CompareVersions, GeneralsOnline-aware). Regression test: ReconcileReleaseUpdateStates_WhenFamilySharesOneVersion_DownloadedSiblingStaysDownloaded.
  • Fixed: "local is newer" reported as not downloaded. A pool holding a newer build of the same source showed NotDownloaded and resolved no manifest, so Add to Profile failed too. Non-multi-release cards now stay Downloaded and resolve the local manifest; multi-release feeds (GitHub/TSH weeklies) keep NotDownloaded per release card. Regression test: GetStateAsync_WhenLocalBuildIsNewerThanCard_StaysDownloadedAndResolvesAsync.
  • Fixed: bundle member updates not actionable. Bundle cards never showed an Update button (ShowUpdateButton excluded bundles) and ready-members counted UpdateAvailable as downloaded. Bundles with outdated members now show Update, ask via the standard update dialog (Downloads.UpdateDialog.BundleMessage), re-download only outdated members, and reconcile game profiles with the old→new member mapping.
  • Fixed: silent update swallow. When a publisher reconciler reported success-but-noop, UpdateContentAsync returned false without asking. It now falls through to the explicit update dialog + download + reconcile flow.
  • Fixed: factory manifests drop origin linkage. Publisher factories rebuild manifests from extracted content, losing OriginalContentId and any download URL, so sibling cards from other publishers could never match. The orchestrator re-stamps origin metadata plus the origin download URL (Publisher.ContentIndexUrl) after prepare, and URL matching now considers it.
  • Fixed: silent catalog drops on export (5 vs 6). Stale hosting URLs (deleted/renamed catalogs) and unpublished candidates were dropped without a word. ExportProviderDefinitionAsync now logs each excluded id so the publisher can prune hosting state and republish.
  • Fixed: bundle save dropped publisher identity. Studio wrote matrix selections into BundledItems with content id only, breaking external members after save. Publisher, version constraint, and catalog URL are now carried over from the prior release dependencies.
  • Data (this repo): removed github/lemon-controlbar from all three bundle releases (bundles use the L3M bar); bundle descriptions now say L3M Modern HD Control Bar. The lemon-controlbar item itself stays as a standalone entry.
