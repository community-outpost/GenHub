1. Ingestion Pipeline & Privacy Architecture

The telemetry subsystem provides production observability across runtime game processes, content delivery, publisher updates, and client health without capturing personally identifiable information.

Engine / UI / CLI Action → TelemetryService.TrackAsync() → Channel<TelemetryEvent> (Bounded: 500) → TelemetrySanitizer (DAG Cycle-Safe Recursion) → AnalyticsTelemetrySink (PostHog /i/v0/e/) & SentryTelemetrySink
Sanitization Invariant
Zero PII
User directories, Wine prefixes, and private tokens masked via regex passes before dispatch.
Batch Delivery
30s / 500 Events
Bounded channel with drop-oldest backpressure protects UI thread and client memory.
Fail-Safe Isolation
Zero Disruptions
Telemetry recording is non-blocking. Sinks run in background tasks with try/catch isolation.
Threadpool Offload
Deadlock-Free
Synchronous restart handlers (Velopack) offload flush operations to Task.Run with ConfigureAwait(false).

4. Post-Deployment Operational Plan

Live Event Validation & Auditing

1. Path Masking Verification: Inspect live PostHog ingest stream (Project 567732) to confirm zero raw user directories exist across executable_path, error_message, or stack_trace.
2. Heartbeat Reliability: Verify active game sessions produce heartbeats every 300 seconds and conclude with game_session_ended containing accurate was_graceful booleans.
3. Failure Ratio Alerts: Configure PostHog action alerts for content_download_failed / (content_download_completed + content_download_failed) > 0.05 and Sentry alerts for fatal app_unhandled_crash occurrences.
